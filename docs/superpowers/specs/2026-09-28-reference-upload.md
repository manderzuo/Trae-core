# API 本地参考图上传衔接

## 范围与根因

TRAE Work CN 的已观测 Chat 请求把本机图片路径放在最新 user 消息的 `<uploaded_files><file_path>` 中，而非 image_url。Core 不可读取远端路径，现有缺图拦截正确，但缺少客户端上传工具回合。

## 设计

对明确的当前图片附件，Core 返回客户端已声明且允许联网的终端工具调用。自包含 PowerShell/Bash 命令读取这些图片，使用短期、仅限本次上传的授权上传至 Core；不下发长期 API Key，不依赖 MCP。服务器保存加密的原请求和逐个附件槽位；工具返回上传完成后，以服务器实际收到的素材恢复原请求。幂等键固定到这次上传会话，工具回传重试不得再次付费。

上传会话绑定 Key、原请求、最多 10 个附件、30 分钟期限；每个槽位只接受一次内容，相同内容重试返回原素材，不同内容拒绝。恢复不相信工具伪造的 asset ID。禁用或轮换 Key 后，短期授权立即失效。无工具、路径无效、上传失败时明确报错且不得提交视频。

只接受客户端附件包装内的绝对 PNG/JPEG/GIF/WebP 路径，不从普通提示词或系统消息收集路径、不读取 UNC/设备路径、不上传非图片。已有 image_url、有效素材 ID、MCP 上传流程保持不变。没有传路径或图片字节的客户端，不能由服务器凭空恢复图片。

## 验收

真实结构回归：上传前无计费；原图哈希一致；视频准备参数包含图片；SSE/非流式；同 Key 两会话不串图；跨 Key、失效授权、失败工具、不同内容重试均拒绝；重复工具回传不重复提交；执行真实 PowerShell/Bash 上传脚本。最后进行一次受控公网带图付费测试，保留任务与结算证据。
