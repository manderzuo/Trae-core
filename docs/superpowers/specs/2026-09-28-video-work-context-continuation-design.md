# 视频作业上下文持久化与自动续写设计

日期：2026-09-28。状态：待用户审阅；本文件不是实现或上线验收报告。

## 1. 目标与范围

同一个对话内，用户可以说“把刚才的视频改成夜景”“动作放慢”“接着上一段再生成5秒”，无需重复提示词、规格和参考素材。Core 保存可恢复的作业、版本和素材关系，辅助模型理解本轮修改意图，视频仍由现有 Seedance 链路生成。

自动续写指自动寻找明确的上一版本、准备其尾帧并提交下一段。只有用户明确要求生成、重新生成或续写时才创建付费视频任务；不会自行无限续写。“不满意”但没有修改方向时先追问；查看状态、重新下载和提取尾帧不新增视频扣费。

本次不包括：自动剪辑合成长视频、精确编辑原 MP4、跨 Key 共享作业、引入新的付费视频供应商，以及无上限长期缓存视频。默认输出续写得到的新片段，原片段不覆盖。

执行方式沿用用户最新要求：由当前主代理直接实施和审计，不启动子代理。当前授权是制定计划，不是部署或提交真实生成。

## 2. 当前证据与支持边界

- Core 基线：6638a27；AI Work 基线：c8428a8；MCP 基线：8f85598。
- Core 的 user_routes.rs::extract_seedance_prompt 只提取最后一条用户消息；budget_flow.rs::seedance_work 的辅助模型输入只有系统指令和该提示词。
- reference_context.rs 支持短期、Key 绑定的素材标记及部分历史图片复用，不是完整作业上下文。Core 普通素材默认有效期约30分钟。
- budget_continuation 是单次请求的故障恢复检查点，不能代替长期作业和版本记录，保留现有用途。
- bridge_planner.rs::video_profile 的白名单只有普通图片/视频参考和规格，没有首帧、尾帧角色。video.rs 使用 TRAE 原生 tool_text_to_video_stream，不是直接调用火山方舟。
- 本机 TRAE 官方 Seedance 插件1.0.1只声明 GenerateVideo，没有给出首尾帧参数契约。
- [火山引擎官方模型表](https://docs.volcengine.com/docs/ark/model-list?lang=zh)列出 Seedance 2.0 Fast 的首帧、首尾帧和视频延长能力。这不能证明 TRAE 原生接口开放了相同字段。

验收时区分三种能力：普通尾帧参考生成、原生指定首帧生成、原生视频延长。后两种必须取得 TRAE 契约和实际结果证据，不能把 HTTP 200 或未知字段被忽略当成能力验证。

## 3. 方案选择

推荐“Core 持久化结构化作业＋有界历史＋按证据选择续写模式”。Core 是作业与归属的唯一事实来源，GLM-5.3-Flash负责识别本轮意图和整理有效提示词，AI Work 负责原生提交、计费归因和从已有视频提帧。

不选择仅转发完整历史：虽然改动较少，但不能恢复素材、容易再次触发大输入限制。也不把每个 Key 绑定一个永久文字会话：同一 Key 的不同电脑和不同对话会串任务。

## 4. 作业与版本模型

新增 Core schema v30，保留全部现有请求、预占、回执和未知占用。升级只新增表，不清理旧账本，也不自动迁移历史视频为“可续写作业”。

新增四个存储单元：

1. video_works：work_id、owner_key_id、owner_user_id、conversation_ref、created_at_ms、updated_at_ms、deleted_at_ms。conversation_ref 由服务端随机产生；有客户端编号时只保存带 Key 和客户端命名空间的哈希映射。
2. video_work_versions：version_id、work_id、parent_version_id、operation_request_id、ordinal、action、state、key_version、encrypted_snapshot、snapshot_sha256、context_handle_sha256、tail_frame_media_id、frame_state、frame_error、created_at_ms、updated_at_ms。operation_request_id 唯一；序号在事务内分配。有效提示词、规格、素材关联和上下文摘要放入加密快照。
3. video_work_media：media_id、work_id、owner_key_id、kind、content_sha256、encrypted_storage_ref、key_version、size_bytes、expires_at_ms、state。以作业归属和摘要去重，不能按公开 URL 或 Key 最近素材复用。
4. video_work_contexts：context_handle_sha256、work_id、version_id（待生成作业可为空）、key_version、encrypted_handle。句柄哈希用于查找，原句柄仅以密文保存，用于重试/重启后的稳定回传；同一作业版本复用一个句柄，不能每次回复覆盖旧句柄。

版本状态：preparing、running、completed、failed、unknown。状态绑定原 operation_request_id；完成视频但下载失败仍是 completed，交付状态单独记录。结算未决与生成状态也分开保存，不伪造已结算。

快照 VideoWorkSnapshot 包含：有效提示词、duration/resolution/ratio/watermark、原始参考素材 ID、派生尾帧 ID、父版本、原任务编号、参考模式、摘要、交付状态。明确区分用户原参考图和上一视频派生尾帧。

不修改旧版本的生成输入。修改和续写生成独立子版本及请求编号；同一版本可以产生多个分支，不能被后完成的任务覆盖。状态、交付及后台尾帧结果可按原请求更新，不能改写有效提示词和预算快照。选定版本以本次显式父版本或对话回传标记为准，不以全局最近完成任务为准。

## 5. 对话续接与无配置兼容

解析优先级：

1. 请求明确提供的 work_context（work_id、base_version_id，可选 conversation_id）。
2. 已验证的客户端对话编号与当前请求中的作业关系。
3. 当前 messages 中服务端曾返回的作业续接标记，优先最近的相关 assistant 结果。
4. 没有任何可靠关联时，创建新的随机作业或追问，不查询 Key 全局最近任务。

新增紧凑标记格式：[AIWORK_WORK:<base64url随机句柄>]。句柄由服务端生成，索引只保存哈希，原句柄加密保存供稳定回放，绑定Key、作业和版本；不能替代API Key，也不能被直接用作下载授权。Key停用、作业删除或版本撤销后无效。标记不放入辅助模型或视频提示词。

响应的 work_context 元数据和 assistant 最终文本都能携带关联信息，兼容忽略自定义元数据的普通 OpenAI 客户端。流式、非流式、上传确认、下载失败回退都要保留该标记。不得依赖客户端新增插件、请求头或修改设置。普通问候和连通性测试不创建视频版本；首次参考素材上传可创建待生成作业，后续正式生成才创建版本。

多标记冲突、用户要求“另一版”但没有唯一候选时，返回简短澄清，不提交视频。显式切换父版本必须先查当前 Key 归属；其他 Key 的编号统一按不可用处理。

客观限制：客户端若既不给对话编号，又没有回传任何服务端标记，两个字节完全相同的首次请求无法可靠地区分为重试或两个新对话。保留现有保守去重保护，不把输入哈希当成持久对话身份；不承诺这一无身份场景的完全区分。受控客户端验收需记录其实际回传了什么。

## 6. 意图、继承与辅助模型

意图枚举：create、revise、continue、status、download、clarify。默认辅助模型保持当前 glm-5.3-flash，不新增另一文字模型。

- create：明确独立生成，不带旧素材和旧场景，创建新作业。
- revise：继承指定父版本，只改变明确提出的提示词与规格。用户取消参考图时清除；新图片默认替换原用户参考图，除非明确要求合并。
- continue：继承人物/画风/场景/分辨率/比例，准备父版本尾帧；新段默认沿用父版本时长，用户本轮指定时长优先。
- status/download：只读取已有任务或走现行下载交付，不准备新视频预算。
- clarify：提示需要哪些修改信息，不生成视频。

参数优先级：本轮显式字段＞本轮文字中的明确规格＞父版本规格＞现有默认值。时长4–15秒、分辨率480p/720p、六种现有画幅不变。全角规格先按现行规则规范化，不静默改动用户比例或秒数。

辅助模型只接收已验证父版本的结构化快照、最近最多4条相关用户文本和本轮文本。总输入序列化上限32KiB，其中历史文本不超过8KiB。图片只用受控素材描述/标识，不传 Base64；不转发终端长输出、下载命令、ticket、API Key 或不相关对话。

输出为严格 JSON：action、effective_prompt、spec_patch、reference_policy、clarification。保留当前1024输出 token 上限；发生截断、无效 JSON、虚构版本或不支持规格时拒绝提交视频，不通过重跑视频补救。辅助模型按现有独立步骤实际结算，不称作免费。

服务端校验归属、参数和引用；辅助模型不能选择账户、变更扣费标准或发起任意 URL 请求。结构化明确状态/下载操作可以在调度前识别；遇到需要模型判断的表达，可能只产生文字模型费用，仍不产生视频费用。

## 7. 作业素材保存与恢复

普通临时上传仍维持现有30分钟规则，不整体延长有效期。用于已确认作业的原图片/参考视频单独复制到私有作业素材区，作为工作副本保存；一次上传之后不能再依赖过期 ticket。

默认作业素材保留30天、单素材沿用32MiB上限、每 Key 上限1GiB、Core 作业素材总上限10GiB；这些是新增持久配置字段，可在部署前按服务器容量调整。作业元数据保留到显式删除。容量统计计算加密后实际文件尺寸，拒绝新持久副本前不驱逐正在使用的素材。

上传时校验文件魔数、类型、大小、归属和摘要，复用现有KeyVault的版本化加密边界。文件原子发布；数据库记录与文件发生故障时可恢复，清理仅处理可确认的孤儿或已过期工作副本。密钥轮换必须涵盖作业快照、关联句柄密文和素材副本。

后续使用时，从私有副本重新生成短期 Core 素材，再走 materialize_bridge_assets 上传 AI Work。不把过期 asset_id 继续传给上游。原用户参考素材丢失/过期时明确要求重新上传，禁止自动降为纯文生成。

已有生成视频沿用 AI Work 私有视频缓存和受控资源恢复，其缓存可用期不等同于作业素材30天。视频完成后后台预提取并保存尾帧为私有作业素材，防止后续仅因源MP4缓存过期就无法续写。版本记录保存请求绑定，不保存长期公开下载链接。不额外长期复制所有MP4到公网Core；源视频无法恢复且尚未保存尾帧时，不新增生成任务去冒充原视频。

运行中的操作对工作副本持有可恢复的媒体租约，直到视频提交完成或确定取消才释放。按版本引用追踪，删除一个分支不得删除其他分支在用的素材。清理不碰现有账本和未知执行占用。

## 8. 自动尾帧准备与能力分级

在 AI Work 增加仅桥接管理员可访问的路由：

    POST /internal/bridge/v2/requests/:request_id/last-frame?budget_id=...

复用现有 content 路由的授权检查：budget_id、request_id、core_key_id、account_ref、已成功执行及加密结果必须一致。只接受内部保存且已完成的源视频，不接受客户端提供的任意 URL、本地路径或 shell 命令。

从已有缓存/受控资源恢复视频后，用受信任固定路径的 FFmpeg 提取最后可解码帧。以视频文件摘要＋提帧算法版本缓存；只在固定私有目录写临时文件，验证 PNG 后原子发布。返回 PNG、尺寸、帧时间戳和来源摘要；Core 将其作为归属明确的派生作业素材保存。

资源边界：提帧并发2、等待队列最多8、单进程超时30秒、输出上限8MiB。解码尾部，不全量读 MP4 到内存，不使用整段 reverse 缓存全部画面。FFmpeg 不通过 shell 启动，限制为本地文件/pipe协议。视频缓存读取期间必须有媒体租约，避免清理与提帧竞态。

提帧属于已有产物处理，不产生视频扣费，不占用付费视频执行租约。完成后的预提帧异步执行，不等待它才返回视频/下载或释放计费额度；结果和异常单独记录。续写时优先用已保存尾帧，缺失时才受控提取；失败仍保留父版本，不重新提交父视频，也不用空参考替代尾帧。

续写模式：

| 模式 | 启用条件 | 返回说明 |
| --- | --- | --- |
| tail_reference | 普通参考图链路＋尾帧提取真实验收通过 | 从上一段尾帧作视觉参考生成新片段，不保证严格首帧匹配 |
| native_first_frame | TRAE 原生字段契约与真实结果均验证通过 | 把上一段尾帧指定为下一段首帧，不承诺动作/音频完全无缝 |
| native_video_extend | TRAE 原生延长契约、输出语义和计费均验证通过 | 原生延长；单独验收，不是本期交付的必要依赖 |

自动模式优先已验证 native_first_frame，否则使用已验证 tail_reference 并明确说明。用户明确要求严格首帧而能力不可用时，提交前返回 continuation_mode_unsupported，不能暗中降级。任何待验证模式默认关闭；不直接照搬方舟 first_frame/last_frame 参数到 TRAE。

能力配置必须包含上游/客户端版本、证据日期、参数映射和证据摘要；升级上游或契约发生变化时重新验证。增加GET /internal/bridge/v2/video-capabilities只读接口。普通生成、已验证图片参考不因严格模式尚未验证而被全局关闭。真实验收前仅对隔离测试Key开放待验收的tail_reference；这不关闭预算或素材保护，原生首帧仍须先取得契约。

## 9. 扣费、幂等与并发

每个新版本对应新的请求和预算操作，沿用现有报价/临近规格预估、有限预占、真实回执校对、规格学习。参考类型按实际图片/视频数量参与报价；不能将带尾帧的任务按无参考任务伪报。

在准备预算前解析父版本并冻结不可变输入快照；重试复用同一快照、素材摘要、辅助模型结果和请求编号。作业绑定是本地短事务，网络、提帧和文字模型调用不在数据库锁内执行。

已有预算操作的恢复优先于重新解析历史，不因素材过期或项目指针更新而改变已提交任务。记录版本失败不能错误取消已发送但结果未知的任务。作业数据库写入失败若发生在付费提交之后，按原 request_id 恢复绑定，禁止重发生成。

读取/下载/提帧不冻结视频额度。确认生成才使用原 Key 并发规则；观察者与执行者仍分离，不新增对话级长锁或把状态轮询算作新任务。实际结算速度和额度释放保持现行机制，不等待客户端下载成功。

## 10. 接口和交付

现有 POST /v1/chat/completions、POST /v1/videos/generations 保持兼容；新增可选 work_context、action、continuation_mode。内部字段在送到 TRAE 前剥离。

新增 GET /v1/video-works/:work_id 读取当前 Key 作业和版本；新增 POST /v1/video-works/:work_id/continue，接收 base_version_id、prompt、可选规格、continuation_mode。新生成接口沿用现有视频任务响应并额外返回 work_context，不创建另一套任务查询协议。

MCP 增加 seedance_continue 与 seedance_work_status；原 submit/generate 可选传作业和父版本进行 revise。旧工具保持可用；等待、查询和下载仍复用现有流程。API直连不依赖 MCP 脚本，服务器不能凭空调用客户端未声明的工具。

客户端交付保持现行已声明工具适配：默认系统 Downloads，显式目录仍按现行规则处理。只有取得真实本地工具回执才显示“已下载”。上传/下载回执不能触发另一个生成版本；下载失败仍提供原视频受控链接和作业标记。

实时反馈只报告已发生的事实：恢复版本、整理修改、准备尾帧、提交新段、上游生成、产物可用、本地交付。重复轮询不重复追加状态段落，不能让 GLM 猜测百分比、完成时间或上游原因。

## 11. 验收与发布门槛

必须通过：同一对话改版继承、显式规格覆盖、参考素材超过普通TTL后复用、跨 Key 拒绝、同 Key 两对话隔离、并发分支、重试单次提交、Core/AI Work重启恢复、素材或父视频丢失不降级、流式/非流式标记续接、工具回执不重生成、真实扣费归因与预占释放。

受控付费最小样本：生成V1（5秒480p带清晰参考图）→同对话修改V2（继承规格与素材）→从V2续写新段C1（5秒480p），主客户端最多3次。完整真实客户端验收按TRAE Work CN API、DSH API、Codex MCP各最多3次，合计最多9次常规生成；能够复用可验证V1时减少次数。严格首帧另安排最多1次，仅在取得原生契约后执行。发布前后共享这个上限，不重复计算。不得未经结果分析连续盲重试；重试同一请求不计为新样本，也不允许再发视频。

每次记录 work/version/parent/request/budget 的关联、实际素材摘要与上游参数、状态时间点、扣费回执、预占释放、本地下载回执；链接与日志脱敏，不暴露永久 Key、JWT 或 ticket。

当前轮不执行测试。实施时先本地与假上游回归；然后在隔离测试 Key 上受控付费验证，再部署公网灰度并进行真实客户端验收。TRAE Work CN API直连、DSH API直连、Codex MCP分别记录结果，合成HTTP测试不能代替客户端工具链验收。

三个仓库分别提交：Core→manderzuo/Trae-core；AI Work→其当前 origin，经实施前核验；MCP→manderzuo/trae-maker-MCP。公网只更新 Core 对应服务，本机更新 AI Work 助手；不得把本地账号助手误部署为公网服务。

上线前备份配置与数据库、核验迁移和版本哈希。回滚先关闭新增特性并使用兼容v30的发布包，不以旧v29二进制盲读新库，不恢复旧数据库覆盖新增付费记录。已有未知占用原样保留。
