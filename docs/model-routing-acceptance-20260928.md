# 模型配置与拒绝请求并发占用修复

## 原因与修复

- `budget_policy_unconfigured` 来源在 AI Work：原本只配置少量文字模型预算。AI Work 配套版本为已支持文字适配器提供有界、模型独立的风险预占；显式管理员策略仍优先。未知模型不再静默转成 DeepSeek。
- Core 普通 Chat 在素材校验、桥接报价/准备失败时提前返回，留下 `received` 请求，后续被错误计入并发。
- 增加原子、受条件保护的未准入请求收尾。只处理没有预占、任务、租约、请求关联、预算操作/步骤、账单证据的请求。
- 阻塞准备线程持有请求所有权，HTTP 断开不能提前释放所有权。结果未知或已派发的任务不会被上述收尾逻辑退款。
- 观察者容量已满时，仅清理尚未被其他观察者持有的新请求。
- 启动恢复追加 V2 预算/准备/账单保护，保留历史流水与未确认费用。

## 未冒充通过的边界

- 第一次图片验收用到 CRC 错误的 PNG，返回 `chat_execution_unknown`；该请求仍保留 10 积分预占并占用一个执行名额，没有无证据退款。后续使用校验正确的图片另发一次有限请求并成功。需要继续补全损坏图片的派发前验证与上游失败诊断/对账。
- 本轮没有重跑付费视频规格矩阵，也未验证官方 Trae 客户端先前单独出现的 `Unknown stream error`。
- 18 个文字适配器有单元覆盖；真实公网抽测上述模型，不等于每个上游模型均已真实生成验收。
- 修复保留在既有修复分支；不自动合并主分支，不更改 MCP 仓库。
