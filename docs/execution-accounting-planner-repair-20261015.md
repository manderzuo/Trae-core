# 执行退出 核账和规划输出修复

本补丁处理 E09-S003 辅助模型生成非法 JSON，以及旧未知任务同时保留积分与并发的问题。正常完成、明确失败和未知结果继续保留各自事实，不以费用状态推断视频成功，也不以本地退出推断上游未收费。

## 规划输出

视频作业规划通过 `submit_video_plan` 函数参数返回五个既有字段。请求指定唯一函数及 schema，关闭并行调用。解析器验证唯一 choice、唯一函数、函数名、结束原因、参数语法、重复键和后续业务规格；混合正文、其他函数或损坏参数仍会拒绝。历史完整 JSON 回复仍可读取。没有增加自动付费修复或视频重提。

小型真实 GLM-5.3-Flash 调用已验证当前桥接支持指定函数、保留台词英文引号和反斜杠。此验证仅调用文字模型，未提交视频。

## 并发与账务分别收尾

Core 接受经过桥接鉴权的 `ConfirmedWorkerExit`。它必须与已存储的 request、Key、budget、账号、桥接实例及可选 task 完全一致。步骤必须为 unknown、已尝试发送、创建超过30分钟；退出观察至少持续60秒，观察必须在5分钟内。兄弟步骤仍有执行时拒绝释放。

释放仅写入既有 `reviewed_worker_absence` 并发审计，不改变积分或未知结果。重复回执幂等，服务重启后仍生效，原身份不能再次付费派发；若观察到真实 running，原有计数逻辑重新计入占用。

AI WORK schema 11 提供持久执行退出记录。未知账务可基于独立退出核账时间点读取完整、精确、最新的原会话账单，不再依赖不存在的 `finished_at_ms`。没有账单、零值候选、来源不完整或身份冲突均不能把未知执行结算成零收费。费用变动继续走既有冲突隔离流程。

## 展示

Key 管理保留 `credits.held` 的总预占含义，新增 `running_held`、`reconciliation_held`，两者之和等于总预占；待核账仍影响可用余额。失败回执新增已知实际扣费与步骤明细，不把缺失金额填零。

## 发布边界

不重提 E09-S003，不恢复自动化10，不修改生产执行器台账。切换前必须确认全局无在途付费执行与待交付结果，备份后采用受控服务切换。Core 本次不改变数据库 schema；AI WORK schema 11 不能直接换回旧二进制。新交易发生后禁止用旧账库覆盖回滚。
