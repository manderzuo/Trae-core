# Seedance 重复连接 429 修复

## 问题与范围

原代码将 HTTP 结果观察者与唯一执行者合并。客户端断线重连、自动重试或同 Key 同请求的同时连接，会在原任务生成中直接收到 `429 budget_observer_busy`，但原任务仍可能继续生成、结算。

本次保持原有按 Key 和请求指纹绑定的幂等身份、执行锁、计费及并发规则，只将客户端等待结果与付费执行解耦。多个连接共享一个内存中的完成通知；只运行一个辅助模型、一个视频及一轮下载调度。原连接离开不会取消已执行任务，新的连接可以继续等待。后台恢复仍与 HTTP 执行者互斥。

完成通知只在任务执行期间保留。结束后仍通过原有数据库账本恢复结果，不改数据库 schema，不清理旧账单或未知扣费记录。不宣称支持多个 Core 实例共享内存订阅；目前部署为单实例。

## 边界

- 只合并通过认证及原有幂等检查的同一任务；不同 Key 不共享结果，不同请求仍受 Key 并发限制。
- 结果等待全局上限 256、单任务 16；在执行的结果通知最多 128。超过真实容量仍限流，区别于正常重复连接。
- SSE 继续提供心跳和最终 `[DONE]`，重连得到同一个结果/下载工具调用。未读取的流受发送超时保护，断线释放观察名额。
- 若后台恢复暂时持有执行权，HTTP 等待它释放后读取已持久化步骤，不重新发送已付费步骤。等待执行权最多 45 分钟，不因超时伪造退款。
- 同 Key 无显式幂等键的相同请求仍遵守原有规则：在执行期间合并，完成后短期重试窗口两分钟；超出窗口主动再次生成不是本次修复的重连保证。

## 验证进度

- 四个原始回归均先复现失败：辅助阶段重复 SSE、视频中断线重连、非流式重复请求、失败任务结果回传；修复后通过。
- 已通过 12 个同时发起的无幂等头请求只生成一次、跨 Key 隔离、不同输入并发限制、下载调度中的重连测试。
- 已覆盖发布者取消、断线释放名额、全局/单任务容量与不同任务独立完成。
- 自审发现执行容量拒绝时清理锁范围回退，新增回归先失败再修复，保留原有清理期间独占保护。
- 本轮自行审阅，不启用子代理；没有未处理的阻塞性审阅发现。
- 最终 Windows 网关完整套件 220 passed / 0 failed，Core 套件 261 passed / 0 failed。
- Linux 重连集成测试 8 passed / 0 failed，Linux release 编译通过。
