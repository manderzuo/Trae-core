# 视频素材下载失败：最多重试一次

用户已授权在上游确认素材下载失败后，最多创建一次新的付费视频尝试。断线、响应未知、一般超时、安全检查失败不触发重新生成。

## Core 接口

- `POST /v1/videos/{original_request_id}/retry`，请求体固定为 `{"max_retries":1}`。
- `GET /v1/videos/{original_request_id}/retry`：只读找回已创建的重试任务编号，供提交回复丢失时恢复查询；不创建任务、不准备预算、不提交上游。
- 需使用原用户、原 Key；提交仍检查 `videos:submit`、视频准入、并发和可用积分。

Core 读取原预算的、身份核验通过的最终失败结果。只接受 `reference_resource_download_failed`，不把所有 `3003` 或 HTTP 超时都当成可重试。

每个原请求使用固定幂等身份 `reference-retry-once:{original_request_id}`。并发或重启后的调用复用同一子请求。子版本永久保存 `retry_source_request_id`，即使旧 checkpoint 被清理，也不能继续创建第二次自动重试。

重试复用加密版本快照中的实际提示词、执行规格、参考素材与续写上下文，重新上传已核验的素材。辅助文字模型不再调用。原失败版本、预算、积分预占和实际回执不重置；新视频有独立预算和回执。重试本身再次失败或结果未知后，只核对这两次尝试，不产生第三次生成。

## Studio 集成

只有已审查部署契约同时声明 `workContext` 和 `videoRetry` 的新确认任务，才冻结 `maxAutomaticRetries:1`。旧任务没有此字段，不追溯执行。

后台在保存已确认失败的原任务时，事务内创建关联子任务并保存 `retryRunId`；子任务保存 `retryOfRunId` 和 `retryOfCoreTaskId`。唯一索引限制同一原任务只有一个重试。关闭页面后后台仍会处理，暂停意图和项目回收状态仍受检查。

## 验证边界

隔离 Bridge/数据库回归覆盖素材重新上传、原提示词保留、辅助模型只调用一次、两笔账务分离、并发与重启、重试再次失败、结果未知、其他错误、跨 Key 隔离和只读找回身份。

此机制不能延长上游内部签名有效期，也不能保证第二次排队不会再次发生素材下载失败。未自动重跑生产历史任务，未以测试为由发起真实付费生成。
